## Fixed design before preparation/inference

All 12 OBSOLETE cases in each public split, 24 total, regardless of previous success. Four conditions, 96 fresh primary local generations:

1. `original`: exact source pack from the frozen v5 treatment; repeated generation measures reproducibility without changing the old output.
2. `oracle_only`: only the gold supporting source.
3. `old_then_new`: forbidden/obsolete source, then supporting source.
4. `new_then_old`: the same two sources in reverse order.

The paired conflict conditions contain identical evidence with different order; they do not change dates, roles, note text or model instructions. Oracle source IDs and family membership are intentionally supplied from public gold for these diagnostic controls. No answer fragments/expected values enter preparation or generation packets. This is not automatic label-blind retrieval. Keep queries, the v5 reader system/role suffix, native answer schema, seed7, temperature0 and installed Qwen2.5 14B digest unchanged. ## Falsification and next decision

- Oracle-only failures contradict the claim that merely removing distractors suffices for this reader/protocol.
- More stale leakage in conflict pairs than oracle-only supports an interference/reader-use diagnosis on these authored cases, not a universal cause or repaired memory architecture.
- Discordant equal-evidence order pairs expose order sensitivity; identical repeated packets can expose generation variability. Report uncertainty and paired outcomes rather than select the best arm after seeing scores.
- No production intervention is selected solely from these24cases. A general candidate must subsequently be checked across every H1 family at declared inference/context cost, then on fresh data.

Record a result and decision even if all controls fail or no gain appears. This is the second pending experiment at most; execute it rather than add more unexecuted designs.
