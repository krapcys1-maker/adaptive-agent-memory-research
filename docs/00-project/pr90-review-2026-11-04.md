## Findings

### R1 — high: resume accepts a different effective profile and mixes prompts

At the reviewed head, [`run_chunked`, lines 745–747](https://github.com/krapcys1-maker/adaptive-agent-memory-research/blob/c7f0321e76b87af20eec70b70d4a1f4df5816840/scripts/persona_battery.py#L745) skips existing answers by key alone. It does not compare the stored prompt digest (`psha`) with the pending task. [`frozen_problems`, lines 814–816](https://github.com/krapcys1-maker/adaptive-agent-memory-research/blob/c7f0321e76b87af20eec70b70d4a1f4df5816840/scripts/persona_battery.py#L814) compares only a prompt fingerprint that omits the effective kernel/profile. The baseline stores more identity information, but resume does not bind itself to that identity.

**Reproduced:** prepare with the freeze enforced; save one injected K answer; change `PERSONA_BATTERY_PROFILE` to `{"min_evidence": 1000.0}`; resume P1 in the same work folder. The freeze reports no problems, the command returns 0, and the resulting 291 synthetic records contain one old prompt digest and 290 records from the changed profile. The extreme threshold makes the discrepancy deterministic; the defect is acceptance of any identity change, not this particular threshold.

**Required fix:** persist an immutable execution manifest covering the effective profile, kernel digest, prompt switches, frozen inputs and relevant configuration. Validate it before any call or resume, including saved records' keys and prompt digests. A changed experimental identity requires a new work folder. Re-running `prepare` over existing answers must not silently reset their identity.

**Acceptance:** interrupted runs resume with unchanged settings; changes in kernel, profile or prompt switches fail before a model call; stale/duplicate/unknown records fail with a useful error. Keep a regression test with `freeze.enforce=true`.

### R2 — medium: analysis attributes old answers to the current shell settings

[`analyse`, lines 1513–1514](https://github.com/krapcys1-maker/adaptive-agent-memory-research/blob/c7f0321e76b87af20eec70b70d4a1f4df5816840/scripts/persona_battery.py#L1513) builds provenance from the currently imported kernel, current script and environment. It neither uses the baseline as execution provenance nor checks for disagreement.

**Reproduced:** prepare and create an answer with the honour-the-record sentence enabled, then analyse with that switch disabled. The command returns 0 and reports `honour_record=false`, although the baseline says true and the actual prompt contained the sentence. A fresh CLI without the original environment has the same problem.

**Required fix:** retain execution provenance from the saved run and record analysis-code provenance separately. Refuse inconsistent or unverifiable attribution. Legacy runs need an explicit compatibility path; do not infer their execution settings from the analyst's current shell.

**Acceptance:** analysis under changed environment settings either preserves verified execution identity or refuses; it never relabels the run. Check legacy 0.1.0, honour variants and 0.2.0 profile variants without modifying their stored artifacts.

### R3 — medium: incomplete stages can receive final registered readings

[`p1_readings`, line 1193](https://github.com/krapcys1-maker/adaptive-agent-memory-research/blob/c7f0321e76b87af20eec70b70d4a1f4df5816840/scripts/persona_battery.py#L1193) applies its instrument threshold to whichever F records happen to exist. [`analyse`, lines 1508–1512](https://github.com/krapcys1-maker/adaptive-agent-memory-research/blob/c7f0321e76b87af20eec70b70d4a1f4df5816840/scripts/persona_battery.py#L1508) has no stage-coverage gate.

**Reproduced:** save one correct F answer from a planned synthetic P1 stage of 291 answers and analyse. The output reports `records.p1=1` and `readings.p1.instrument_ok=true`, with no incomplete-stage status.

**Required fix:** calculate expected key/cell coverage for the requested stage, report completion explicitly, and withhold registered readings until their required observations and labels are complete. Descriptive partial summaries can remain available. Separately planned P1-only and P2-only amendments must remain valid; do not require absent, unrequested stages.

**Acceptance:** partial, duplicate, missing and unmatched data cannot produce a final pass. Completed single-stage amendment runs still produce their correct readings.
