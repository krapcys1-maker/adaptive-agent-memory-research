# Project delivery and evidence audit — 4 November 2026

**Verdict: a working research memory tool, reusable components and substantial experiments exist. A generally capable adaptive memory product has not been delivered or validated.** Green software checks establish implementation properties; they cannot supply the missing end-to-end capability. The new hard test exposes the weakness of a particular raw-line kernel adapter, not the worthlessness of the entire repository.

The owner requested this audit after the recent eight-field pilot and the hard-test failure were communicated too broadly. This report checks code, Git/PR history, recorded experiments and the local NIE integration. It separates measured outcomes, author attribution and inferred process causes. Main before this work was `6099cdb9f9ed0f055c2f405253a7eac3db01fe9e`; new hard-test/audit work is a separate branch based on it. No production behavior or original worktree was changed for this audit.

## Audit findings and causes

**A1 — High: the language-to-memory boundary is still not generic.** The reference AAMR adapter calls the service-domain `address_extract` rules at ingest and query. Records that fail addressing never enter its drawers. The existing known-outcome failure on external question forms is documented in [issue 47](https://github.com/krapcys1-maker/adaptive-agent-memory-research/issues/47); the model-extracted/hybrid arm is not delivered. This audit re-ran the unchanged adapter on the new archive without a model or gold: zero drawers, 0/100 question addresses, 0/100 non-abstentions. This is a verified limitation of that negative prototype, not a newly discovered bug in a claimed generic implementation.

**A2 — High: no single demonstrated product closes capture → addressing → revision → retrieval → raw answer.** The [foundation decision](../04-systems/foundation-v0-architecture-decision.md) explicitly accepts a minimum comparison floor, not a final architecture. The store, kernel, address/resolver experiments, context packs and integration hooks are useful pieces, but successful tests often provide one piece's missing input by construction. Supplying the right address or typed claim does not earn that boundary. The inspected entry points and recorded runs do not demonstrate the complete generic product the owner expects.

**A3 — High: software correctness was repeatedly communicated as progress toward a stronger claim than it tests.** Main's last complete gate had 2956 passing software tests and 20 skips. The new complete local code gate passes 2981 tests with 20 skipped; the earlier collection snapshot includes 867 LifeSim tests and the new harness checks. These counts protect code/instruments; they are not 2999 independently successful memory tasks or live model answers. The recent summaries gave too much prominence to 48/48 and green CI, even while limitations were present in the documents. Codex should have led with the unresolved product boundary and prior failed P2 reading.

**A4 — High: the older negative findings did not become closed delivery milestones.** The registry has 74 rows, including 20 blocked on corpus work (four also on review); November experiments are separately tracked. The operating doctrine defines research success as a recorded decision, including a negative one. That is a valid research objective, but it is different from delivering a reliable memory product. The observed pattern is many instruments, designs and small mechanism studies while generic addressing and an integrated acceptance run remain open. This is an inference from the artifacts, not an assertion about anyone's intent or hours spent.

**A5 — High: today's hard score must remain scoped to its adapter and settings.** [The full 100-question hard variant](../../data/lab/hard-memory-external-v1/README.md) gives K 0/100 on both readers, B 4/100 Flash and 1/100 local. It stores raw lines, uses a small evidence budget, no inferred state chains, a non-thinking Flash reader and a short answer protocol. It is not the official full-agent MemoryAgentBench harness and not a test of every AAMR component. Initially attributing the failure only to a missing retrieval loop was premature. The already launched [local iterative follow-up](../../data/lab/hard-memory-iterative-v1/scores.json) achieved only 4/100 after 402 primary rounds. Two separately frozen post-hoc evidence-complete Flash controls achieved **1/2**. These observations leave retrieval, representation, prompt and reader reasoning failures in play; they do not establish one exclusive cause or a repaired system.

**A6 — Medium: prior mechanism work was not consulted early enough in the latest repair.** The August [second-hop mechanism G](../research/SECOND_HOP_ASSOCIATIVE_EXPANSION_V1.md) already appended new items on 2/6 cases but repaired none; blind top-hit expansion drifted away from the question. The new six-round query-guided experiment differs in method, yet should have referenced that evidence before being described as filling an entirely absent capability. Existing work must be reused or explicitly distinguished rather than rediscovered. No novelty or generalisation claim is made for the new failed development follow-up.

**A7 — Medium: research and integration status are easy to confuse.** A read-only shadow, a dark persona module, a pre-existing bounded history injection, an offline adapter and a model API benchmark are different operational states. The local NIE flags/return paths show that the inspected shadow contributes no prompt text and persona generation is disabled locally, while the older E23 `on` history path does supply selected recent material. A research PR merge does not change any of these. Production server state remains unverified; this audit does not infer it from local flags or claim that NIE has no memory at all.

**A8 — Medium: comparator and authorship labels need boundaries.** Old Mem0/Hindsight runs prove that comparisons occurred, not that today's versions were beaten. Commit usernames shared by agents do not justify assigning every artifact to Claude. Explicit Claude coauthor commits substantiate the November kernel, LifeSim and persona battery; dated Codex receipts substantiate the latest integrity/diagnostic work. The earlier August authorship is not fully recoverable from Git metadata alone. Responsibility for the recent overbroad progress summaries is Codex's.

## Immediate corrections and next admissible work

1. Put the current failure and scope at the top of `CURRENT_STATE`, the delivery overview and GitHub status. Preserve the earlier correct narrow results; do not rewrite them as false or erase negative runs.
2. Make one runnable memory pipeline and its inputs the delivery unit. Identify which existing store/addressing/state/retrieval components it actually uses; require natural question text, provenance, explicit stale/unknown behavior and raw generated answers. Close the missing addressing/capture boundary from existing issues rather than add another unrelated architecture diagram.
3. Keep three measurements separate: evidence preserved, supporting evidence actually shown, and final answer correct/current. Use a matched evidence-complete reader control to avoid blaming retrieval for an unsupported causal diagnosis. Retain same-budget baselines and failure traces.
4. Develop changes on explicitly spent data, then freeze a transfer run on another corpus before any broad promotion. The current iterative 4/100 is a failed development result, not evidence that the problem is solved. BEAM-10M, LongMemEval-V2 and MemoryArena remain documented candidates; cached data is not a passed test.
5. Treat actual NIE integration as a separate acceptance step under its ownership. Validate local/offline first, preserve personality and improvisation/write-back, then measure the actual configured agent. Do not turn an internal UNKNOWN recall signal into a blanket refusal policy or overwrite an existing fact after a retrieval miss.

No new feature repair was started after the owner's explicit switch to an audit. The already launched local run was completed, frozen and scored as evidence; two narrowly budgeted reader controls checked the audit's causal interpretation. Original code, negative results, frozen kernels, old worktrees and NIE remain preserved. This audit changes the delivery assessment and documentation; it does not declare the product finished.
